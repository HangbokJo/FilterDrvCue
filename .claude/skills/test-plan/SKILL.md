# 검증 점검

## 절차
1. 설계 문서(`docs/design/`)가 있으면 "완료 기준"을 읽는다.
2. 변경된 코드에 대해 아래 케이스 목록을 만든다.
3. 이미 있는 테스트·확인 절차와 비교해 빠진 케이스를 표로 정리한다.
4. 호스트에서 가능한 것(빌드, 분석, INF 검증, 사용자 모드 테스트 코드)을 실행한다.
5. 테스트 시스템이 필요한 항목은 절차를 문서로 작성하고, 실행하지 못했으면 미확인으로 표시한다.

## 호스트에서 확인
- 경고 0 빌드 (`/W4 /WX`)
- 코드 분석 (`/p:RunCodeAnalysis=true`), SDV
- `infverif /w` INF 검증
- 사용자 모드 헬퍼/테스트 앱이 있으면 빌드와 실행

## 테스트 시스템에서 확인 (사용자가 준비한 VM/PC에서만)
- Driver Verifier 켠 상태(특수 풀, IRQL 검사, DDI 준수)로 로드
- 설치 → 제거 → 재설치
- 장치 비활성화·활성화, 케이블 제거·재연결
- 절전 진입·복귀
- 재생·녹음 중 언로드/제거
- 기본 오디오 재생·녹음 동작, 끊김·지연 여부
- IOCTL 잘못된 입력(길이 0, 너무 짧은/긴 버퍼, 널 포인터)
- 회귀: 필터 없을 때와 같은 동작을 유지하는가

## 좋은 검증 기준
- 구현 세부사항이 아니라 **동작**을 검증한다
- 항목 하나는 한 가지만 확인한다
- 이름만 읽어도 무엇을 검증하는지 알 수 있다
- 검증을 통과시키려고 기준을 고치지 않는다. 실패하면 코드를 고친다

## 보고
```
| 케이스 | 상태 |
|---|---|
| 경고 0 빌드 | ✅ 통과 |
| 절전 복귀 | ⚠️ 테스트 시스템 없음, 미확인 |

msbuild: 경고 0, 오류 0 / infverif: 통과
```
확인하지 못한 항목은 이유와 함께 명시한다.
