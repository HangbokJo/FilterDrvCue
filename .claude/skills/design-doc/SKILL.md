# 설계 문서 작성

코드를 쓰기 전에 설계를 확정합니다. 이 단계에서는 코드를 수정하지 않습니다.

## 절차
1. 관련 코드를 읽고 현재 구조를 파악한다.
2. 요구사항이 모호하면 추측하지 말고 사용자에게 질문한다.
3. 아래 양식으로 `docs/design/<기능명>.md`를 작성한다.
4. 사용자에게 검토를 요청하고, 승인을 받은 뒤에만 개발을 시작한다.

## 양식

```markdown
# <기능명>

## 목표
무엇을, 왜 만드는가 (2~3문장)

## 범위
- 포함:
- 제외:

## 장치 스택
- 필터 위치: 상위/하위, 장치 노드/인터페이스 노드 (대상: USB\VID_2360&PID_7011)
- 연동하는 드라이버(예: usbaudio 계열)와 선택 이유
- 가로채거나 변경하는 요청 종류

## 설계
- 변경할 파일과 각각의 역할
- 주요 클래스/구조체와 WDF 콜백 구성 (장치·큐·요청 컨텍스트)
- 요청 흐름 (수신 → 처리 → 전달/완료)
- IRQL과 락 전략
- PnP·전원 처리 (제거, 절전, 비활성화)
- 사용자 모드 인터페이스(IOCTL) 정의: 코드, 버퍼링 방식, 입출력 구조
- INF 설치 방식, 서명·배포 방법

## 대안과 선택 이유
검토한 다른 방법과 이 방법을 고른 이유

## 위험 요소
오디오 스트림 끊김/지연, 블루스크린 가능성, 기존 드라이버와의 충돌, 호환성

## 작업 순서
1.
2.

## 완료 기준
어떤 빌드·분석·테스트 시스템 확인이 통과하면 끝인가
```

설계는 짧게 유지한다. 한 화면을 넘으면 범위를 줄일 수 있는지 먼저 검토한다.
